# 钱包与账本迁移（V20）

对应旧 app/api/wallet.py 六个接口，以及 admin_billing.py 的交易/账户查询两个接口。礼物退款、支付订单/回调、直播分账和通话扣费仍由后续业务迁移接入内部账本，不代表这些业务已完成。

## 已实现的约束

- 金币使用 bigint 整数；对钱包、金币账户、分录及兼容流水在同一数据库事务内更新。
- 每笔交易正负分录合计必须为零，正向总额须与交易金额一致。数据库延迟触发器在提交时再次检查收支平衡及分录数量。
- 已入账的交易和流水不能 UPDATE/DELETE，修正应使用新冲正交易。没有给普通用户提供账本写入/转账接口。
- 同一幂等键配合相同业务参数只入账一次；不同金额、用途或备注返回 409。元数据对象的键顺序不影响幂等。
- 相关用户按稳定顺序加锁后操作账户；并发扣款不能透支。溢出、冻结、会话失效和部分写入失败都会整体回滚。
- 钱包余额与账本账户不一致时返回对账错误，禁止继续静默入账。Java 独立空库初始为零；旧余额导入必须另行设计对账迁移，不自动复制旧数据。
- 用户只看到自己的分录；owner/operator/auditor 可在各自 billing.read 权限内查询完整账本。管理员禁用和令牌失效检查仍有效。
- 注销后继续保留匿名账号标识下的账务历史和余额，不级联删除账本；已注销用户无法继续交易。

## 本地模拟

生产默认配置和普通本地启动均关闭开发充值。显式使用 tools/start-local.ps1 -DevelopmentSms -DevelopmentAdmin -DevelopmentBilling 才开放本地合成金币充值；JAVA_APP_ENV=production 时，即使打开模拟开关也会拒绝。

这不是实际支付。V20 未声称调用微信支付、回调验签或真实资金入账。

## 验证

WalletIntegrationTests 使用真实 PostgreSQL 和 HTTP 验证并发幂等、并发扣款、双向内部转账锁顺序、收支平衡、数据库不可变历史、写入失败回滚、金额上界、权限和注销留存。

tools/smoke-wallet-local.ps1 检查运行中的本地服务，报告见 docs/local-wallet-smoke.json。测试数量及部署版本以 migration-status.json 的最终记录为准。
