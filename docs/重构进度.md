## 短信与推送的完成边界

- 目前只有 development 短信适配器，无真实短信发送。默认 provider=disabled；未配置时返回 503。
- 本地启动必须显式指定 `tools/start-local.ps1 -DevelopmentSms` 才启用测试验证码回传，监听地址仍为 127.0.0.1。
- 验证码 6 位，5 分钟有效，5 次错误后锁定；摘要使用独立密钥 HMAC-SHA256，不持久化明文验证码。
- 错误次数在返回 400/429 后仍持久化；业务失败则回滚成功验证码消费，允许恢复后重试。
- 对验证码发送做数据库原子预留，再在事务外调用适配器。状态分 pending/sent/failed，未完成发送的码不可消费；较旧发送不能覆盖较新请求。
- 429 返回重试详情和 Retry-After；错误验证码返回 remaining_attempts。
- 密码重置用途保持旧契约的 `password_reset`。旧腾讯适配器出现过 `reset_password` 命名，后续真实适配时不得照搬。
- 真实腾讯云 Java 适配器、模板配置、错误映射及真实送达验收尚未完成；不接受 tencent_cloud 配置后假装发送成功。
- 推送设备 CRUD 已完成；消息投递、供应商 token 有效性、账号切换时 token 归属策略尚待推送模块验收。
- 手机客户端、云端、验证码自动填充及整页交互未联调。

### 权限与凭证

管理员使用独立表和用途派生签名密钥。普通用户令牌不能访问后台，管理员令牌也不能当作用户令牌或图片预览令牌。身份、账号状态、密码摘要指纹、token_version 和角色权限均查数据库，不信任 JWT 中缓存的角色。登录限流为直接 IP 每分钟 10 次。

本轮 owner 有 admin.manage、moderation.read/write、operation_logs.read；auditor 有 moderation.read/write；operator 当前仅能登录、查看自身及改密/退出，旧版的用户运营、举报、支付等权限将在相应模块迁移时补齐，暂不返回虚假的可用功能。

改密、重置、禁用、重新启用和退出会递增 token_version；重新启用不会恢复旧令牌。退出当前实现为撤销该管理员全部令牌，尚无逐设备后台会话模型。当前密码在事务外验证和派生，事务内再次核对当前身份状态，防止并发改密后凭旧密码继续操作。

账号管理采用全局数据库事务锁避免多 owner 交叉禁用死锁；进入事务后再次核对操作人，已通过两个 owner 并发禁用场景测试，保留一个可用 owner。

### 生命周期规则

保持旧版 45 天冷静期。冷静期内允许登录与恢复；到期后恢复返回 403。只靠客户端时钟不能提前清理，执行时在数据库用户锁下重新检查状态和截止时间。恢复完成后执行早期清理不会删除资料。

申请注销记录与状态同事务，重复请求不延长期限；恢复与取消任务也同事务。清理后的原手机号可以注册新 user_id，但旧 token、会话和原身份不会恢复。

当前关闭 Worker 时，即使已经到期，也不会在开发库自动执行清理；到期账号会停留在 deactivation_pending，恢复仍按截止时间拒绝。这是明确的开发运行状态，不代表已部署可运营的注销流程。

### 数据清理策略（仅覆盖目前迁入 Java 的表）

- 删除本人资料、资料审核记录、推送设备、会话、通知偏好、通知变更待投递记录、双向拉黑关系，以及收件人或发起人为该账号的通知。
- 删除本人媒体元数据和媒体审核记录，物理文件以独立 storage_deletion_jobs 入队；受管理媒体签名因元数据消失而失效。
- 删除该手机号已有验证码。保留 users 引用墓碑，替换手机号和密码，清空会员状态及注销申请时间，设置 deactivated 和注销完成时间。
- 保留必要的账号清理计数与现有认证事件类型/结果，移除认证事件的会话关联和请求标识；清空该用户/媒体相关后台操作日志 details，避免留存审核正文。
- 资金账本、聊天、动态、支付、群组等尚未迁移，预览不会为这些领域虚报清理计数或已完成保留策略。

V6 新增 account_erasure_records、storage_deletion_jobs 及到期索引，V1～V5 未修改。每个直接引用 users.id 的外键必须出现在 USER_FK_POLICY 中，集成测试从 PostgreSQL 实际外键结构核对；未来迁移新领域须补充策略与测试。

### 事务、并发及文件任务

数据库清理在单用户事务内完成，失败则回滚。批次失败记录为 failed，仅保存固定错误码，等待下一次重试；不将数据库异常正文或用户数据放入错误字段。

验证码发送/消费和清理统一按手机号事务锁、用户锁、验证码/业务行的顺序执行。推送及通知写入补充用户行锁和状态复查；密码、资料、媒体等原有用户锁继续生效，避免认证通过但排队中的请求在清理后重新写入账号数据。

数据库清理成功但文件未删除时记录为 storage_pending，直到全部文件任务完成才进入 completed。文件删除以任务行锁领取，失败保存固定错误码并延后 60 秒，文件已不存在按成功处理；完成后清空内部存储键。临时数据库测试验证清理重试和幂等。

Worker 每次最多处理 20 个到期账号、100 个文件任务，计划间隔 60 秒。**当前不开启，不提供公开手动强制删除 API。**
