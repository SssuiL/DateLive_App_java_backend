# 实时通信迁移（V10）

本轮提供 2 个 WebSocket 入口，HTTP 接口仍为 74 个。范围是好友私聊和通知中心；没有切换 Flutter，也没有接入直播信令或厂商离线推送。

## 连接与鉴权

- `/ws/messages?reliable=true`：消息、已读/送达回执、撤回、本人隐藏/清空、输入状态和在线状态。
- `/ws/notifications?reliable=true`：通知中心未读数。
- 优先用 `Authorization: Bearer <access_token>`；为旧客户端保留查询参数 `token`。查询参数可能进入外部代理访问日志，部署代理时须脱敏；应用不输出令牌。
- 握手和每次消息处理均校验登录；服务轮询也复核令牌、会话撤销、过期和账号状态。退出、撤销或注销后连接自动关闭。
- 浏览器沿用 Spring 默认同源限制；原生客户端可不带 Origin。跨域网页接入需要单独配置具体可信来源。
- 首帧为 `{"type":"realtime.ready","channel":"messages","cursor":"0","protocol_version":1}`。
- 通知连接另发一次当前未读数快照，该快照没有 event_id。

## ACK 与断线恢复

需要可靠投递的客户端显式传 `reliable=true`。服务端持久事件的 event_id 是十进制**字符串**，避免客户端整数精度丢失。

1. 收到有 event_id 的业务事件，先按 ID 去重并应用到本地状态。
2. 按接收顺序逐条发送 `{"type":"ack","event_id":"123"}`。这是逐条确认，不能跳过前面的待确认事件；确认伪造或未发送的 ID 会断开连接。
3. 服务端返回 `{"type":"ack.confirmed","event_id":"123"}`，在数据库保存登录会话/通道的最大已确认 ID。
4. 断线重连不传 cursor 时从该登录会话的已确认位置恢复；也支持显式 `cursor=123`。显式游标须是本账号、通道允许的范围，客户端应使用已保存的位置。游标本身不产生送达/已读回执。
5. 新登录会话有独立检查点；共享同一登录令牌的多个连接共享检查点。需要独立离线进度的设备应各自登录取得独立会话。

最早未确认事件在约 3 秒后重新发送；最多保留 64 条待确认事件，超过 30 秒未确认则关闭连接（1013），客户端重连恢复。因此语义是**至少一次投递，客户端按 event_id 去重**，不是网络层恰好一次。

撤回、隐藏、清空、屏蔽及注销可能使旧事件不再可见。重放和重试都重新读取当前可见状态，已不可见的事件跳过，撤回事件只给出脱敏内容。客户端遇到失效确认导致的断开，应重连并刷新会话列表/消息历史，以 HTTP 当前状态为准。

不传 reliable=true 的兼容连接仍接收事件，但不提供上述自动重试和 64 条 ACK 背压；未 ACK 不更新送达回执。现有 Flutter 尚未适配此 ACK 协议。

## 事件

| type | 主要字段 / 语义 |
| --- | --- |
| message.created | conversation_id、message（当前可见完整消息） |
| message.recalled | conversation_id、message（撤回后的脱敏消息） |
| message.delivered | conversation_id、message_id、delivered_to_user_ids |
| message.read | conversation_id、message_ids、reader_user_id；只包含接收者可见的 ID |
| message.hidden | conversation_id、message_id；仅本人各连接 |
| conversation.cleared | conversation_id；仅本人各连接 |
| notification.unread_count | unread_count；通知中心计数，与聊天未读数独立 |
| typing.start / typing.stop | conversation_id、user_id；仅当前好友对端 |
| presence.updated | user_id、online、last_seen_at；即时快照，无 event_id |

输入状态通过发送 `{"type":"typing.start","conversation_id":"..."}` 或 typing.stop 触发，间隔至少 500 毫秒，有效期 5 秒，不作为长期状态恢复。客户端应自行超时隐藏“正在输入”。

消息送达 ACK 只更新接收者 delivered_at，不更改 read_at 或聊天未读数。个人隐藏和清空不会广播给对方，也不会伪造已读回执。

## 心跳、在线和多实例

- 客户端建议每 30 秒发送 `{"type":"ping"}`，服务回复 pong；60 秒无客户端活动断开。
- messages 连接每 15 秒续期数据库在线租约，租约有效 45 秒；进程崩溃后在线状态最多滞后一个租约周期。
- last_seen_at 是连接/续期时刻，不保证精确到断开瞬间。
- 在线查询还要求登录会话未撤销、未过期且账号正常。通知通道不使聊天在线。
- 当前每用户最多 8 条连接（跨实例、含两通道），每实例最多 200 条；输入帧最多 8 KiB、每分钟 1200 条，发送缓冲 64 KiB。
- 多实例共用 PostgreSQL 事件和租约表，无进程内单例投递假设。测试实际启动两个 Spring Boot 实例验证跨实例发布与接收。
- 事件生成使用事务级串行锁保证提交顺序与游标顺序一致；当前存在数据库轮询和按会话查询，**尚未完成高并发容量压测**，上述连接上限不是吞吐承诺。

## 持久化与失败重试

V10 新增 realtime_events、realtime_checkpoints、realtime_connections、用户最近在线时间以及 outbox 重试字段。

业务事务先写 chat_change_outbox / notification_change_outbox；默认开启的 worker 每约 500 毫秒读取待处理项，将每位接收者事件与源 outbox 状态放在同一事务提交。唯一键防重复发布。失败记录通用错误码并按 5–60 秒退避重试。

源 outbox 的 delivered_at 现在表示**已交给持久实时事件队列**，不能据此判断客户端收到了消息。客户端送达以消息回执为准。事件正文按发送时的权限和状态动态读取。

注销清理已覆盖实时事件（作为接收者或操作者）、检查点、连接及最近在线时间，并随私人会话级联清除相关记录。自动注销清理仍开启。

当前事件历史与过期输入事件没有独立的按时间回收任务，主要随账号/会话清理。上线前需确定事件保留时长、过旧游标重新同步协议及容量监控；不能直接把本版本作为长期无限保留的生产配置。
