# 媒体异步处理与草稿回收（V16）

## 接口

- POST /media/upload?async=true：使用现有 multipart 字段，先持久化原始数据与任务，返回媒体对象。支持 PNG/JPEG/GIF、语音、视频和普通文件。
- GET /media/{id}：仅上传者可查询单个资产；不存在、已删除或非本人返回 404，失效会话返回 401。
- GET /media/me：包含排队、就绪和失败的未删除资产。
- 不传 async 或传 false 时保持同步上传。Flutter 代码未修改，当前 Flutter 调用仍是同步；接入异步时需传参并轮询 processing_status。

HTTP 200 表示接受上传，不代表媒体可用。processing_status 为 queued、ready 或 failed；status 分别从 uploaded 转为 review_pending 或 rejected。任务正在运行时，对外仍是 queued，直到事务提交。只有 ready 且满足原有审核/绑定/权限要求才允许预览、签名访问、资料引用或消息发送。ready 不代表审核通过。

queued/failed 不返回可用预览、衍生图或探测元数据。失败可读取 processing_error（稳定错误码，不包含原始内容、路径或异常正文）；临时错误重试成功后清空。失败任务需要重新上传，没有无限重试接口。

## 持久化和容量

V16 在媒体表新增处理状态/错误码/完成时间，增加 media_processing_jobs。已有资产按 ready 迁移，processed_at 保留原 created_at；V1–V15 未修改。

本阶段使用独立 PostgreSQL bytea 保存有界原始输入，媒体记录和任务原子提交；原始输入不能通过下载接口读取。成功、永久失败、取消、草稿回收和到期注销均删除任务及其原始数据。没有新增外部消息服务依赖。

- 每用户最多 4 个任务，全局最多 20 个任务，待处理原始数据总计最多 256 MiB；超限返回 429 MEDIA_QUEUE_FULL。
- 图片/语音输入上限 8 MiB，视频/普通文件 32 MiB；空文件、明显不支持的 MIME 或超大请求直接拒绝。
- 入队时仍执行好友/会话与账号检查，以及原有每 IP 上传频率限制。
- 实际解码、格式/轨道/时长校验与规范化在 Worker 中执行，复用此前已验证的处理器；普通文件仍没有真实病毒扫描。

## 执行、重试和恢复

Worker 启动 5 秒后运行，每次处理 1 个任务，每轮结束后等待 1 秒。数据库事务级咨询锁保证本数据库同时只有一个异步处理者；媒体调度使用独立单线程，与实时事件和其他后台调度分开。

一次处理在持有用户行锁、媒体行锁的事务内完成：清理同资产上次未提交的文件、处理、更新元数据并移除任务。删除/注销会等待或先完成，Worker 随后重新检查记录，因此不会在已删除资产上重新发布文件。进程中断或数据库发布失败会回滚事务，任务保留；下次执行先清理可能残留的输出，再重新处理。

确定性输入错误直接 failed；IO、工具不可用、处理繁忙等临时错误间隔 30 秒重试，累计 3 次已记录的失败后进入 failed。进程崩溃或数据库事务失败不消耗已提交失败次数，仍受草稿保留期约束。失败输出无法访问，文件清理失败保留存储键，由清理 Worker 继续重试。

这是面向当前单机环境的持久化队列。转码期间会占用一个数据库连接和该用户的行锁；现已通过本地脚本拆分无 HTTP 的独立 Worker，尚未采用租约式任务领取或容器资源配额，不能把本轮验证当成生产吞吐证明。扩容到多节点前必须配置共享对象存储并验证资源、锁等待和容量。独立 Worker 每小时清理超过 24 小时的已知处理器临时文件，保留新文件、未知文件和目录。

## 草稿回收

默认保留 24 小时，启动 60 秒后检查，每轮最多 50 项，每轮结束后等待 60 秒。仅回收超过保留期且满足以下全部条件的资产：

- 未删除且没有 message_id；
- 没有消息通过 media_asset_id 引用；
- 没有资料的当前头像、待审核头像、当前照片或待审核照片引用。

在用户、资料、媒体锁内再次核验上述条件。已绑定消息（包括隐藏/撤回消息）保持原生命周期，不因为草稿任务被清理。未引用的 queued、ready、failed、rejected 均适用；回收移除任务原始数据并触发整套存储删除。保留软删除媒体记录供既有关系和排查使用。

此规则仅覆盖当前已实现的资料与私聊。后续群聊、动态等模块引入新引用时，必须先扩展引用检查，再启用对应媒体用途。

## 配置与复验

| 环境变量 | 默认 | 用途 |
| --- | --- | --- |
| JAVA_MEDIA_JOBS_WORKER_ENABLED | true | 是否执行排队任务；关闭后仍可接受有界队列 |
| JAVA_MEDIA_DRAFT_WORKER_ENABLED | true | 是否回收超期未引用媒体 |
| JAVA_MEDIA_DRAFT_RETENTION_HOURS | 24 | 保留小时数，至少 1 小时 |

账号到期注销 Worker 保持用户授权的开启状态，独立于上述配置。

18 项 MediaJobsIntegrationTests 使用隔离 PostgreSQL：覆盖 HTTP 入队/状态/越权、PNG/GIF/文件/音视频处理、容量和并发、失败与重试、任务插入和结果发布回滚、新 Worker 恢复、并发删除、双参与者注销、草稿状态/引用/竞态。

本机脚本 tools/smoke-media-jobs-local.ps1 会暂停媒体 Worker、上传合成图片与视频、取消一个任务，再实际重启 Java API 验证持久化恢复、输入失败、人工审核、发送、缩略图解码、Range、隐藏撤权和文件清理。它不会修改本地账号注销期限或草稿创建时间。结果写入 docs/local-media-jobs-smoke.json。
