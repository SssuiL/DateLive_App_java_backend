# 直播送礼迁移（V26）

## 已实现

- 活跃房间成员送礼；禁止主播给自己送礼，主播必须具备收礼资格。
- 礼物目录价格与资源快照、1–99 数量、5 秒连击、累计 100 上限、10 秒 10 次限制。
- 同一用户请求号只扣一次；修改房间、礼物、数量或显式连击号返回冲突。房间结束后不接受重试送礼。
- 单笔、UTC 单日消费限额，成人核验状态，高额送礼二次确认（5 分钟、绑定用户/房间/礼物/数量/金额且只能使用一次）。
- 扣款、70% 主播应付收益、平台收入、礼物记录、确认消费和房间热度在同一数据库事务提交。
- 收益使用整数乘 7 除 10，按每笔向下取整，避免旧浮点算法的舍入误差。1 金币礼物产生 0 主播收益，不创建 0 金额账本分录。
- 失败的风险拦截保留风险记录；余额不足不消费确认。数据库故障回滚整笔送礼。
- 房间礼物记录、隐私榜单、主播收益记录/汇总、7 天收益成熟、管理员只读审计。
- 注销清理确认、成员与预检数据；保留礼物账务、关联已匿名化用户和关闭的房间。关联账务的风险记录清空详情；无账务关联的个人风险记录删除。

## 实际边界

此批实现金币账务，没有执行现金转账或接入真实直播供应商。礼物退款、结算申请/审核/支付标记、直播 WebSocket 广播仍待后续迁移。年龄状态来自此前实现的管理员审核，不能代表外部实名认证接入。7 天成熟目前使用原项目默认值，尚未开放部署参数。
