# 支付订单与回调（V21）

迁移旧 payments.py 五个接口、payment_callbacks.py 一个接口、admin_payments.py 两个接口。保留套餐价格、用户订单查询及 Mock 完成契约；不在客户端提供可控制的充值金额字段。

## 订单与账本

- 同一用户/请求号只能创建一笔订单。不同套餐或服务商返回 409。
- 本地订单先提交，调用外部支付时不持有数据库事务。失败后保留原商户订单号；30 秒下单占用期防止并发重复调用，进程中断后可重试。此处有意改进旧服务网络失败后回滚订单的行为。
- 同一事件重复到达只处理一次；相同事件号但不同业务数据返回 409。订单与服务商交易号分别约束唯一性，防止不同事件或不同订单重复发行金币。
- 回调核对金额、币种、交易号、付款时间和订单状态。迟到但在订单到期前实际付款的有效通知可入账；过期后付款需人工核对，不自动发行金币。
- 订单、回调审计、金币账户和账本在同一事务提交；错误不会留下半笔入账。
- 已验证的到账通知仍可记入已封禁或注销用户的留存账号，但金币账户自身冻结时入账会失败并等待重试。不会恢复登录、社交数据或消费权限。
- 保留账务记录；回调审计保存业务摘要和指纹，不保存原始通知、支付用户身份资料或密钥。

## 服务商与默认开关

采用微信支付官方 Java SDK 0.2.17 的公钥模式，处理请求签名、响应验签、APP 调起参数签名和回调 AES-GCM 解密；另外检查回调时间窗口、AppID、商户号与 APP 支付类型。依据 [官方 SDK 文档](https://github.com/wechatpay-apiv3/wechatpay-java) 及 [APIv3 签名验签说明](https://pay.wechatpay.cn/doc/v3/merchant/4012365342)。

默认 provider=disabled，Mock 与微信支付均关闭。本地仅显式 -DevelopmentPayments 开启 Mock，并生成存于 .tools/local-development.json 的独立回调测试密钥；本地启动脚本始终关闭真实微信支付。生产环境即使设置 mock-enabled 也会拒绝 Mock。

真实微信支付配置项位于 application.properties 的 JAVA_WECHAT_PAY_* 环境变量映射：商户号、AppID、商户证书序列号、商户私钥文件路径、微信支付公钥文件路径/ID、APIv3 密钥和 HTTPS 通知地址。凭证不得写入仓库或聊天；配置后需要重启以更新缓存的 SDK 配置。尚未启用证书模式或自动公钥轮换。

微信支付成功回调返回 SUCCESS；业务核对失败返回 400，数据库失败返回 500，避免错误确认入账。Mock 回调保留旧审计对象响应。签名验证使用原始请求体，回调大小限制为 64 KiB。

## 验证边界

PaymentIntegrationTests 验证真实 PostgreSQL/HTTP 下的订单、HMAC 回调、并发、重试、过期、权限和回滚。PaymentGatewayTests 使用临时 RSA 密钥及真实 AES-GCM，拦截官方 SDK 网络传输以验证请求/应答/APP 参数签名；不会连接真实支付网关。

tools/smoke-payments-local.ps1 检查运行中服务的 Mock 订单和签名回调。完整回归数量与最终本机结果见 migration-status.json 和 docs/local-payments-smoke.json。

真实商户配置、公网回调、微信客户端拉起支付、真实收款/退款及对账仍待联调。本批不是生产支付验收；礼物退款与通话/直播分账继续迁移。
