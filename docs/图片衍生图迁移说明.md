# 图片衍生图迁移说明（V15）

## 行为与接口

复用现有媒体上传、用户访问签名和管理员预览接口，无新增路由。

| 输入 | thumbnail | display |
| --- | --- | --- |
| PNG/JPEG | 最长边 320 的 PNG | 最长边 1280 的 PNG |
| GIF | 首帧静态 PNG，最长边 320 | 规范化后的原 GIF，保留动画 |

按比例缩放，不放大小图；保留透明像素。GIF 首帧按逻辑画布、帧偏移、背景和透明信息合成。PNG/JPEG 原图仍使用原有规范化 PNG，原文件字节和消息绑定不会被回填修改。

上传响应的 derivatives 提供 thumbnail/display 的 variant、content_type 和 max_edge。通过 POST /media/{id}/access-url?variant=thumbnail 或 variant=display 取得短期签名地址；管理员预览同样接受 variant。变体写入签名，不能通过下载查询参数替换；用户令牌续签保留变体。下载支持已有单段 Range。

完成衍生图的图片 pipeline_version 为 java-image-v2 或 java-gif-v2；回填前保留 v1，不宣传尚未生成的变体。内部就绪标志与重试时间不暴露到用户媒体响应。

## 新上传和旧图片

- 新上传在当前请求中同步完成原图规范化与衍生图生成，共享现有图片解码并发限制。写入临时文件后原子替换；所有文件就绪后才插入媒体记录。生成或数据库插入失败会尝试清理整套文件。
- V15 只增加就绪标志、重试时间和待处理索引，V1–V14 不变。旧 Java 图片在启动 10 秒后开始补生成，每轮最多 10 项，每轮结束后等待 60 秒；失败项推迟 5 分钟再试。
- 回填使用用户锁、媒体行锁，顺序与删除和账号注销一致；事务内重新检查状态，避免删除后重新生成文件。不同实例对同一资产串行处理。
- 可通过 Spring 属性 app.media.derivatives-worker-enabled=false 关闭回填。这个 Worker 仅用于旧图片补生成，通用异步媒体处理队列尚未完成。

## 权限与清理

缩略图和展示图沿用原媒体的审核、资料引用、会话绑定、参与者、拉黑、隐藏、撤回及登录会话校验。签名本身不能绕过实时权限检查。

显式删除与到期注销会清理原图及衍生图；某个文件删除失败时仍尝试删除其余文件，并保留失败状态供原有清理机制重试。GIF display 复用原文件，不产生额外动画副本。

## 验证

- ImageDerivativeIntegrationTests：尺寸/透明像素、不放大小图、GIF 动画、变体签名、续签、Range、审核、资料引用、隐藏/撤回/拉黑/登出、旧图片回填与失败重试、数据库回滚、注销清理、并发回填与删除。
- ImageDerivativesTests：衍生文件写失败后的清理、部分删除重试、GIF 首帧偏移与背景/透明合成。
- 本机复验脚本：tools/smoke-derivatives-local.ps1；使用合成图片与独立 Java 测试账号，验证上传、审核、发送、图片解码尺寸、GIF 帧数、签名下载、Range、隐藏/撤回及文件删除。

后续仍需异步处理、草稿回收、资源隔离与容量测试、云存储、真实安全扫描/内容审核，以及 Flutter 真机联调。
