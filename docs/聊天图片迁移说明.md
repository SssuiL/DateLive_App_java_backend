# 聊天图片与静态贴纸迁移（V11）

本文保留 V11 阶段的图片范围与验收记录；后续 V12 已接入语音，最新语音支持和限制见 [语音消息迁移说明](语音消息迁移说明.md)。

本轮复用现有接口，规范入口仍为 **74 个 HTTP + 2 个 WebSocket**。支持好友私聊中的 PNG/JPEG 图片和静态贴纸；语音、视频、动态 GIF、普通文件、群聊附件及云存储仍待迁移。

## 客户端流程

1. `POST /media/upload` 使用 multipart：
   - media_type=image
   - source=chat
   - conversation_id=当前好友会话 ID
   - file=PNG/JPEG 文件，Content-Type 必须匹配实际内容
2. 返回独立媒体 ID，初始 status=review_pending；上传者可预览，对端不能提前取得附件。
3. 管理员通过现有审核 API 审核。查询支持 source=chat、conversation_id、message_id；本轮没有接入真实自动内容审核供应商。
4. 审核通过后调用现有消息发送 API：

```json
{
  "type": "image",
  "content": "[图片]",
  "media_asset_id": "media_...",
  "media_kind": "image",
  "client_message_id": "独立且稳定的重试标识"
}
```

静态贴纸使用 type=image、media_kind=sticker；内容仍是已经重新编码的静态 PNG。media_kind 默认 image。content 保留旧契约的必填 1–2000 字符，可作为占位或说明文字；不从 content 中的 URL 下载文件。

5. 对端经 HTTP 历史或 WebSocket message.created 获得 media_asset_id，再调用 `POST /media/{id}/access-url` 获取 5 分钟有效的受控下载地址。
6. 实时协议仍需 reliable=true、顺序 ACK、event_id 去重和心跳，详见 [实时通信迁移说明](实时通信迁移说明.md)。

Flutter 尚未改动或切换，不表示客户端已完成这一流程。所有语音/视频/动态 GIF 请求明确拒绝，不以图片接口模拟成功。

## 上传与绑定约束

- 上传和发送都要求当前有效登录、双方账号正常、会话成员身份、好友关系且未被双向屏蔽。
- 上传前先检查会话访问权；存储后在同一业务锁顺序下再次校验。数据库写入失败会删除刚存储的文件。
- 输入最多 8 MiB、400 万像素；仅接收真实 PNG/JPEG 并重新编码成 PNG，去除原文件附带元数据。重新编码结果最多 16 MiB。
- 保留现有单并发图像解码保护；繁忙返回 429，客户端应退避。
- 仅发送本人、当前会话、source=chat、已审核通过且具有有效存储记录的图片。
- 每个媒体只允许绑定一条消息。重试用同一 client_message_id 返回同一消息；更换正文、类型、媒体或贴纸类型则返回 409。
- 消息、媒体绑定、回执、未读数、通知与 outbox 同事务提交。任何环节失败均回滚，附件保持未绑定，可重试。
- 聊天媒体不能作为公开头像/相册；资料图片也不能直接作为聊天附件。需要重新上传到目标用途，避免公开/私密范围混用。

## 可见性与访问撤销

- 未绑定图片：仅上传者可预览；审核通过仍不会自动向对端公开。
- 绑定后：要求有效会话、成员访问权、审核通过、原消息未撤回且本人未隐藏。
- 图片链接在每次读取时重新检查权限；隐藏、个人清空、撤回、拉黑、拒绝审核、删除媒体及登录失效都会使对应旧地址失效。
- 个人隐藏/清空只撤销本人权限，另一成员仍能查看。
- 删除好友保留历史图片访问，但不允许新上传或新发送；与现有文字历史语义一致。
- 撤回后消息中的 media_asset_id、media_kind 置空。拒绝审核或媒体被删除时，历史/重放也不返回可用附件 ID；不能靠旧 ID 重新取得下载链接。
- 已经下载到设备的文件不可能由后端远程收回；本轮保证后续授权访问被拒绝。
- /media/me 保留本人媒体元数据，但对已经不可访问的图片 preview_url 返回 null，不因单个无权限资源导致整个列表失败。
- 管理员审核预览继续使用独立管理员权限与审计，不复用普通会话下载身份。

## 与旧 Python 的明确差异

沿用上传、消息、历史、搜索、审核、下载的路径及主要字段。以下行为收紧：

- 聊天图片必须在上传时绑定目标会话，不能跨用途/会话复用。
- 待审核图片不能发送；不启用旧内测媒体审核绕过逻辑。
- 一图一消息绑定，不允许用一个媒体 ID 挂到多条消息。相同请求重试仍幂等。
- 只开放已具备真实处理能力的 PNG/JPEG 与静态贴纸；GIF、语音、视频和普通文件暂不开放。
- 图片和文本 duration_seconds 只接受省略或 0。

以上差异需在后续 Flutter 联调时验收；未通过改动旧客户端来隐藏差异。

## V11 与注销清理

- media_assets 增加 source、conversation_id、message_id，原资料媒体默认 source=profile。
- messages 增加 media_asset_id、media_kind，并将类型约束扩展到 text/image。
- 媒体与消息分别设置唯一绑定索引；媒体删除时消息外键可置空。
- 私人会话随账号注销清除时，会清理**该会话双方上传的图片，包括未发送草稿**。否则接收者发来的图片会失去上下文却残留存储。
- 注销预览计数采用同一范围。媒体记录、审核记录和存储删除任务与注销事务一起提交；实际文件删除沿用可重试任务。
- 不涉及此账号的其他会话或资料媒体保留。注销失败时双方图片、消息及删除任务全部回滚。
- 自动到期注销 Worker 保持开启；本地冒烟不调整注销期限、不强制清理。
